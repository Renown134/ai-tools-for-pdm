# Карточка кейса «Кто выгуливает Бориса»

> ЧЕРНОВИК, подготовленный ИИ-агентом по явной задаче студента 2026-11-13. Финальную версию формирует и принимает студент; форматы и требования карточки определяются программой обучения.

## Название

«Кто выгуливает Бориса» — учебный micro-MVP для вымышленной компании «Догяндекс».

## Гипотеза

Если сотрудник видит только пять понятных слотов на сегодня и состояние каждого слота, он может самостоятельно выбрать свободный слот и зафиксировать запись без обращения к администратору.

## Главный сценарий

1. Сотрудник открывает общую страницу и видит текущую дату и пять слотов (09:00–17:00).
2. Выбирает свободный слот, вводит ФИО, подтверждает запись.
3. Слот становится занятым, в нём отображается введённое ФИО.
4. Другой сотрудник при попытке занять тот же слот получает понятный отказ сервера.
5. После обновления страницы или во втором браузере состояние то же (SQLite).

Дополнительная функция: карточка «Последнее кормление» с отметкой нового кормления по ФИО.

## Что построено

- Node.js-сервер без внешних зависимостей (встроенный `node:sqlite`, Node 22.5+): раздача страницы и JSON API (`/api/slots`, `/api/slots/book`, `/api/feedings`, `/api/feedings/latest`).
- Защита от двойной записи — одна атомарная SQL-операция `UPDATE ... WHERE booked_by IS NULL`; конфликт возвращается с кодом 409 и понятным сообщением.
- Одна страница без фреймворков (`public/index.html`): слоты, ввод ФИО, карточка кормления; адаптивная вёрстка.
- Хранение — настоящий SQLite-файл `boris.db` в папке проекта; слоты на текущую дату создаются автоматически.

## Границы

Намеренно не входит: авторизация, роли, отмена записи, календарь на неделю, уведомления, интеграции, деплой, масштабирование. Это учебный micro-MVP, все данные синтетические.
