### Этап 3. Серверное поведение ✅ (выполнено 2026-11-12)

Задачи:

- `GET /api/slots`: текущая дата и состояние пяти слотов.
- `POST /api/slots/book`: ФИО непустое после удаления лишних пробелов; сервер изменяет только свободный слот одной атомарной операцией (`UPDATE ... WHERE booked_by IS NULL`); при попытке занять занятый слот — 409 с понятным сообщением, первоначальная запись не меняется.
- `POST /api/feedings` и `GET /api/feedings/latest`: последнее кормление и отметка нового.

Проверка (фактически, 2026-11-12): запись успешна; повторная запись в занятый слот — 409, ФИО не перезаписано; пустое ФИО — 400; неизвестное время — 404.

DoD: 4 (серверная часть), серверная основа для 3 и 5.

## Правила работы (кратко, из `AGENTS.md`)

- Одна явно сформулированная задача за итерацию; решение о принятии изменения — за студентом.
- Постоянное состояние — только SQLite по схеме из `spec.md`, без `localStorage`, моков и состояния в памяти.
- Защита от повторной записи — атомарно на сервере, не только скрытием кнопки.
- Только синтетические данные; без авторизации, отмены записи, календаря на неделю, уведомлений, интеграций и деплоя.
- Commit, push, публикация и удаление данных — только по явному запросу студента.
